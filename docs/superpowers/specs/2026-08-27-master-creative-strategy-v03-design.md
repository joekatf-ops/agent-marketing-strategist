## Purpose

Replace the superseded Persona x Outcome x Angle model with Joe's locked, brand-neutral creative
operating system while retaining the v0.2 brand isolation, evidence, website refresh, portability,
security and approved-revision learning systems.

This is a breaking strategy release. It changes concept identity, initial execution counts,
awareness treatment, source classification, launch structure, observation timing, budget guidance,
naming and test history.

## Source hierarchy

Universal method and brand truth have separate canonical sources.

1. The Master Creative Strategy Notion hub and its current subpages are canonical for the universal
   method.
2. The repository is the reviewed portable snapshot of that universal method.
3. The connected brand folder is canonical for brand-specific truth, evidence and retained learning.
4. A generated brand bundle is a portable snapshot of the brand folder.
5. Conversation memory is never canonical.

If the Notion method changes, a read-only check may identify the change. No connector or LLM may
automatically rewrite the repository or promote the change. A human approves and publishes a new
repository version.

## Goals

- Define one concept coordinate as one Who paired with one primary Problem.
- Build one initial four-ad test batch for each coordinate.
- Preserve clear separation between coordinate, test batch and execution variables.
- Create launch-ready manual Meta names, budgets, destinations and campaign structure.
- Preserve test history even when an iteration retains the same coordinate.
- Add a governed scaling handoff without requiring live Meta access.
- Add structured destination requirements and test-level retained learning.
- Keep every runtime and connector guide portable across supported LLMs.

## Core strategy model

### Concept coordinate

The concept coordinate is:

`Who x Primary Problem`

Who is a recognisable person or broad segment. Use only the lenses that change the message:
identity, situation, behaviour, motivation and experience.

Primary Problem is one problem, frustration, tension or unmet desire. Supporting lenses are
symptom, functional problem, emotional problem, deeper problem, failed alternative and consequence.

The coordinate is enduring. Changing Who or Primary Problem creates a new coordinate. Changing
awareness, messaging route, hook, format, creator, proof, offer presentation, visual execution or
destination does not create a new coordinate.

### Messaging route

Messaging route is the persuasive argument inside an execution. Supported routes include how it
works, reframe, versus the old way, proof that can be seen, objection resolution, mechanism,
demonstration, comparison, story and belief shift.

The term angle may appear in historical records, but it is not a concept axis and must not appear in
new concept equations, cards, names or register fields.

### Concept test

A concept test is a batch launched against one coordinate. Every NNT, INSPO or ITR batch receives a
new sequential `CONTST###` even when it keeps a prior coordinate.

Every initial NNT or INSPO concept test contains exactly four standalone ads:

1. Unaware, code UWA, recognition job, default landing-page destination.
2. Problem Aware, code PRA, diagnosis job, default landing-page destination.
3. Solution Aware, code SLA, differentiation job, default product-detail-page destination.
4. Product Aware, code PDA, decision job, default product-detail-page destination.

Most Aware remains part of awareness theory but is not a standard ad. It is handled by the landing
page, product page, offer and conversion environment. Deliberate HP or other destination exceptions
are allowed only when the execution and destination remain congruent and the exception is recorded.

Initial tests intentionally make large changes across awareness, messaging route, format and
destination. Results identify strong complete executions and create hypotheses. They do not prove
that one isolated variable caused the outcome.

### Source classification

- NNT is a genuinely new Who or Primary Problem hypothesis.
- INSPO adapts an external format, hook architecture, demonstration, narrative, proof presentation,
  offer presentation or messaging route without copying identity, claims, assets, language or script.
- ITR is an evidence-led follow-up that retains Who and Primary Problem while changing one or more
  execution variables.

Every new source batch receives a new CONTST number. No fixed NNT, INSPO or ITR percentage is a
universal default. The mix follows evidence maturity.

## Research output

Retain the current evidence classes, ledger, Voice of Customer bank, sophistication analysis,
competitor map, claim ceiling, contradictions and confidence labels.

The Customer Intelligence Brief must additionally end with:

1. A prioritised list of possible Who definitions.
2. A prioritised list of primary Problems.
3. Evidence supporting each proposed Who x Problem pairing.
4. Commercial and claim constraints.
5. Open questions the creative test should answer.

An early brand may have fewer supported definitions. Counts never justify invented certainty.

## Hook, copy and production behavior

Retain the six-hook development system as a pre-production option set for an approved execution.
It does not create six launch ads. Each selected execution receives one coherent opening made from a
visual hook, spoken or written hook and on-screen anchor that all communicate the same idea.

Retain two lead routes and short, medium and long primary text for each route, plus five headlines,
two descriptions and one CTA for a selected ad.

Every production artefact carries:

- CONTST test ID
- source classification
- Who
- Primary Problem
- awareness code and job
- messaging route
- primary hook
- media type and execution format
- proof and claims required
- destination
- CTA
- people, assets and location required
- complete final ad name ending in `POSTIDXXX`

## Campaign and budget structure

One product and one region have one creative-testing campaign and, after winners exist, one scaling
campaign.

### Creative testing

- Budget type: ABO.
- One CONTST batch per ad set.
- Exactly four initial ads per ad set.
- Absolute floor: $50 per ad set per day.
- Preferred starting point: approximately $100 per ad set per day.
- Higher budgets are set from price, target CAC, capital and account context.
- Planned observation window: five full days.
- Routine creative changes are prohibited during the observation window.
- Intervention is allowed for operational failure, broken destination, policy issue or unacceptable
  commercial risk.

The expected purchases at target CAC remain part of read validity. A five-day review may still be
directional or too early for a verdict when spend or purchase thresholds are not met.

### Scaling

- Budget type: CBO.
- Created only when useful winners exist.
- Graduated ads keep their real Post ID.
- Scale failure is recorded separately from initial-test performance.
- Winners that retain acceptable economics at higher spend enter the evergreen winner library.
- Evidence-led ITR batches continue from testing and scaling signals.

## Naming

Use underscores only. No version suffix is allowed.

### Test ID

`CONTST###`

The prefix is locked and the number is never reused. Every NNT, INSPO or ITR batch gets the next
number.

### Campaign

`[BRAND]_[PRODUCT]_[CT|SC]_[ABO|CBO]_[REGION]_[YYYYMMDD]`

### Ad set

`[CONTST###]_[NNT|INSPO|ITR]_[WHO]_[PROBLEM]`

### Ad

`[FULL_AD_SET_NAME]_[UWA|PRA|SLA|PDA]_[FORMAT]_[LP|PDP|HP|CP]_[POSTID]`

The complete ad-set name is inherited without abbreviation. New ads end with `POSTIDXXX`, replaced
with the real Post ID after publication. Controlled format codes begin with UGC, VSL, FOUNDER, DEMO,
TESTIMONIAL, STATIC, CAROUSEL and COMPARISON. New codes require a genuinely different production
format.

## Brand-folder state

The brand template must support the new model without mixing brands.

### brand.yml

- Keep brand identity, markets, currency, website monitoring, approvals and runtime fields.
- Replace configurable concept prefix and next concept number with locked test prefix `CONTST` and
  `next_test_number`.
- Add controlled brand, product and region naming codes.
- Add testing defaults for the $50 floor, $100 preferred budget and five-day observation window.

### concept-register.yml

Store enduring coordinate records with coordinate key, Who, Primary Problem, evidence references,
status and linked CONTST batches. Retain rejected and archived coordinates.

### test-register.yml

Store each sequential CONTST batch, source, coordinate key, campaign, ad set, four ad names,
budget, observation window, launch status, results, verdict, explanation confidence and next action.

### winner-library.yml

Store graduated ads, real Post IDs, testing result, scaling result, current status and linked ITR
batches.

The generated brand bundle includes these approved structured summaries but continues to exclude raw
evidence, raw revision history and credentials.

## Output contracts

Update the existing readiness, customer intelligence, concept batch, hook batch, ad copy, video,
static and diagnosis contracts. Add:

1. Campaign Launch Plan for manual campaign creation and launch validation.
2. Destination Handoff for ad-to-page message continuity.

The diagnosis contract retains manual files, screenshots and tables as its source. It must record
what was tested, what happened, strongest and weakest executions, likely explanation, confidence and
next action: keep, ITR, stop or scale.

## Learning

Approved human-revision learning remains append-only, scoped and approval-gated.

Test learning is a separate record class. A test record stores observations and explanations without
turning a broad-test association into isolated causation. An ITR may be proposed from a directional
signal. Universal method changes still require separate human approval.

## Notion and Composio governance

Add a connector guide for a read-only Composio Notion check. It documents page retrieval,
completeness checks and the fallback when the account is not connected. It stores no token and does
not claim that connector documentation proves a live connection.

The repository snapshot records source page ID, last edited time and review date. A detected change
produces a review-needed status, not an automatic skill edit.

## Acceptance criteria

1. No active instruction defines a concept as Persona x Outcome x Angle.
2. No standard ad contract or naming rule creates a Most Aware ad.
3. Initial NNT and INSPO tests require UWA, PRA, SLA and PDA.
4. New routes, hooks and formats against the same Who x Problem do not create a new coordinate.
5. Every NNT, INSPO and ITR batch receives a new sequential CONTST ID.
6. Test planning uses ABO, a $50 daily floor, approximately $100 preferred and five full days.
7. Scaling guidance uses CBO and preserves the real Post ID.
8. Campaign, ad-set and ad names follow the locked full formats.
9. Research outputs prioritised Who definitions, Problems, pairing evidence, constraints and open
   test questions.
10. Production outputs carry every required traceability field.
11. Test, coordinate and winner history travel in safe brand bundles.
12. Notion checks are read-only and never mutate the skill automatically.
13. Existing brand isolation, crawl freshness, claim safety, revision learning and secret rejection
   tests remain green.
14. The universal bundle contains the v0.3 references, contracts and connector guidance.
